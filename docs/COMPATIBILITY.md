# Compatibility matrix

Baseline: aiogram `3.30.0` (`c1b0353ce3d3f8d70f90469038939a956e9e09f7`) and Telegram Bot API `10.2`.

| Surface | Current status | Evidence / contract |
| --- | --- | --- |
| Telegram objects | Generated inventory complete | 390 entities, 1,896/1,896 final aiogram field annotations, unknown-field preservation; aiogram-specific bound object helpers are tracked separately |
| Telegram unions | Generated inventory complete | 35 aliases; tagged unions use discriminators, untagged unions use serde matching |
| Telegram enums | Generated inventory complete | 38 enums with serde, parsing, display and string/number conversion |
| Telegram methods | Generated inventory complete | 185 payloads, 980/980 final aiogram field annotations, all 41 `Default(...)` property-to-wire-field mappings with an independent AST fingerprint, typed/union responses, fluent optional fields, and 185 `Bot` entry points |
| Bound object helpers | Implemented for pinned baseline | All 187 upstream `aliases.yml` shortcuts are generated for 11 Telegram types, including replies and ephemeral validation; `Message.send_copy` covers all 15 upstream branches; content/event, names/mentions, URLs, reply parameters, HTML/Markdown, UTF-16 entities and all 12 `Downloadable` types have public helpers and contracts |
| Bot client | Implemented for pinned baseline | JSON/multipart, byte/filesystem/URL uploads, token-based identity/hash semantics, typed error taxonomy, retry/migration/decode handling, per-call timeout, generated exact default-property aliases with per-field suppression, production/test/local API servers, custom reqwest client, request middleware, buffered/streaming and structural `Downloadable` downloads |
| Dispatcher/router | Implemented for pinned baseline | All named update observers, nested routers, observer root filters and scoped inner/outer middleware, typed/raw-JSON update feed, typed DI/filter injection, flags, class handlers, error and recursive lifecycle observers, propagation, multi-bot concurrent polling, backoff, programmatic stop and graceful shutdown |
| Filters | Implemented for pinned baseline | Commands with parsed injection, Unicode casefold and start-anchored regex, logical composition, magic nested fields/items, Python truthiness, string/numeric/bitwise transforms, collection selectors, typed func/cast, comparisons and all five regex modes, callbacks, content type, state, dependency/error and chat-member transitions; Python dynamic syntax maps to typed Rust operations |
| FSM | Implemented for pinned baseline | Five strategies, memory/Redis/MongoDB storage, manual context resolution, state groups with automatic nested-name qualification, middleware, simple and distributed Redis isolation, bounded rollback history, scene registry/builders, state-gated observers, lifecycle actions and `After` navigation; live Redis/MongoDB contracts run in CI; Python class inheritance maps to `SceneBuilder` composition |
| Webhook | Implemented for pinned baseline | Framework-neutral foreground/background feed, constant-time secret validation, Telegram IPv4 allow-list with proxy resolution, JSON/multipart direct replies, cached token-based multi-bot routing, Axum integration and a graceful server runner; both in-process and live TCP/HTTP contracts are covered |
| Utilities | Implemented for pinned baseline | Typed callback data, keyboard/media builders, composable UTF-16 entity formatting, entity-preserving UTF-16 slices, typed text/caption/poll/gift application with default parse-mode suppression, HTML/MarkdownV2 decorations and sections, links/payloads/serialization/backoff, callback answers/chat actions, token/Login Widget/HMAC+Ed25519 WebApp validation, GNU MO plural catalogs, lazy translations and three i18n middleware strategies; Python-only metaprogramming maps to native Rust traits/types/diagnostics |
| Framework public surface drift | Pinned and checked | CI fingerprints 168 public classes, 71 public functions and 531 public methods across the 95 hand-written Python modules, so an upstream API edit requires an explicit compatibility review even when no module is added or removed |
| Framework symbol accounting | Fully routed for pinned baseline | All 770 unique public hand-written symbols across 77 modules are assigned an exact route in [`compatibility/manual-api-routes.toml`](../compatibility/manual-api-routes.toml): 420 native mappings, 335 semantic Rust mappings and 15 Python-runtime facilities supplied by the Rust language; CI verifies route completeness, evidence paths and an independent mapping fingerprint |
| Examples/contracts | Implemented for pinned baseline | All 14 logical workflows from the pinned upstream `examples/` tree map to 19 compiling Cargo examples; unit, generated-drift, live storage and live webhook contracts exercise the framework surface |
| Publishing | Prepared, not executed | Package contents and tag/version release gate are verified; GitHub remote/repository and crates.io publication are intentionally deferred until the parity gate is met |

`Implemented for pinned baseline` means the capability has a public idiomatic Rust equivalent and test evidence. Syntax that only exists because Python is dynamic is mapped rather than copied literally; the module-by-module rationale is in [`PUBLIC_API_MAP.md`](PUBLIC_API_MAP.md). `parity-candidate` remains distinct from a published `1.0.0`: the release gate, API review and publication must still complete.
